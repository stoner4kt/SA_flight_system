## 4. MIGRATION: migrations/002_popia_dsr.sql

Write this file exactly. It depends on 001 running first (fn_touch_updated_at must exist).

CREATE TABLE popia_dsr_requests (
  id              UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
  request_type    TEXT NOT NULL CHECK (request_type IN ('access','erasure','correction','objection')),
  subject_email   TEXT NOT NULL,
  subject_name    TEXT,
  verify_token    TEXT NOT NULL,
  verified_at     TIMESTAMPTZ,
  status          TEXT NOT NULL DEFAULT 'pending'
                  CHECK (status IN ('pending','verified','processing','completed','rejected')),
  completed_at    TIMESTAMPTZ,
  completed_by    UUID REFERENCES auth.users(id),
  notes           TEXT,
  created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at      TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE UNIQUE INDEX idx_popia_dsr_token  ON popia_dsr_requests (verify_token);
CREATE INDEX idx_popia_dsr_email         ON popia_dsr_requests (lower(subject_email));
CREATE INDEX idx_popia_dsr_status        ON popia_dsr_requests (status, created_at DESC);

ALTER TABLE popia_dsr_requests ENABLE ROW LEVEL SECURITY;

CREATE POLICY "authenticated_agents_manage_dsr"
  ON popia_dsr_requests FOR ALL TO authenticated USING (TRUE) WITH CHECK (TRUE);

CREATE POLICY "block_anon_dsr"
  ON popia_dsr_requests FOR ALL TO anon USING (FALSE);

CREATE TRIGGER trg_popia_dsr_updated_at
  BEFORE UPDATE ON popia_dsr_requests
  FOR EACH ROW EXECUTE FUNCTION fn_touch_updated_at();

-- Enable Realtime for live dashboard updates
ALTER PUBLICATION supabase_realtime ADD TABLE fleet_assignments;
ALTER PUBLICATION supabase_realtime ADD TABLE popia_dsr_requests;

-- Add client_email to itineraries if it does not already exist
ALTER TABLE itineraries ADD COLUMN IF NOT EXISTS client_email TEXT;
CREATE INDEX IF NOT EXISTS idx_itineraries_client_email ON itineraries (lower(client_email));

### 7a. src/utils/supabaseAdmin.js

Singleton server-side Supabase client using the service role key.

getAdminClient() returns the singleton, creating it on first call.
Options: { auth: { persistSession: false, autoRefreshToken: false } }
Throws a clear error if SUPABASE_URL or SUPABASE_SERVICE_ROLE_KEY are not set.
NEVER import this file from any client-side code.

### 7b. src/middleware/auth.js

requireAuth(req, res, next) middleware.

Reads the JWT from Authorization header (Bearer token).
If no token: return 401 { error: 'UNAUTHORIZED', message: 'No token provided' }

Validates the JWT by calling supabase.auth.getUser(token) using a client
created with the ANON key (public key verification, no service role needed here).

If invalid or expired: return 401 { error: 'UNAUTHORIZED', message: 'Invalid or expired token' }
If valid: set req.user = user and call next().

### 7c. src/middleware/rateLimiter.js

rateLimiter(maxRequests, windowMs) returns Express middleware.

Uses Cloudflare KV (global.__CF_KV_RATE_LIMIT__) in production.
Falls back to an in-memory Map in local development.
IP detection order: cf-connecting-ip -> x-forwarded-for -> req.socket.remoteAddress -> 'unknown'
KV key format: rl:{ip}
KV value: JSON { count: number, resetAt: timestamp }
KV TTL: Math.ceil(windowMs / 1000) seconds

On limit exceeded: set Retry-After header, return 429 { error: 'RATE_LIMITED', message: '...' }
Clean up expired in-memory entries every 100 requests to prevent memory leak.

## 8. POPIA CONTROLLER: src/controllers/popiaController.js

Register routes in this order. Auth is applied per-route, not to the whole router,
because some routes are public (DSR submission, token verification) and some are agent-only.

POST   /api/popia/dsr          PUBLIC — rate limited (3 per IP per hour)
GET    /api/popia/verify/:token PUBLIC — no rate limit (token is one-time use)
GET    /api/popia/dsr           AGENT ONLY (requireAuth)
PATCH  /api/popia/dsr/:id       AGENT ONLY (requireAuth)

POST /api/popia/dsr:
  Validate: request_type in ['access','erasure','correction','objection']
  Validate: subject_email format
  Generate verify_token: crypto.randomBytes(32).toString('hex')
  Insert into popia_dsr_requests using getAdminClient()
  Send verification email via sendPOPIAVerificationEmail() from emailItineraryCompiler — non-blocking
  Return 202 { message: 'Verification email sent. Check your inbox.', ref: dsr.id }
  On DB error: return 500 { error: 'SERVER_ERROR' } — never expose raw Supabase error externally

GET /api/popia/verify/:token:
  Validate token format: /^[0-9a-f]{64}$/
  Fetch from popia_dsr_requests where verify_token = token
  If not found: return 404 { error: 'TOKEN_NOT_FOUND' }
  If created_at older than 48 hours: return 410 { error: 'TOKEN_EXPIRED', message: '...' }
  If verified_at is already set: return 200 { message: 'Already verified. Request is being processed.' }
  Update: set verified_at = NOW(), status = 'verified'
  Send DPO notification via sendDPONotification() — non-blocking
  Return 200 { message: 'Identity verified. We will respond within 30 days as required by POPIA §23.' }

GET /api/popia/dsr (agent):
  Query params: status (optional filter), page (default 1), limit (default 20)
  Return paginated list with total count
  Sort: verified_at DESC NULLS LAST

PATCH /api/popia/dsr/:id (agent):
  Validate status is one of: verified, processing, completed, rejected
  Update the record
  If status becomes 'completed' AND original request_type is 'erasure':
    Call executeErasure(dsrId, subjectEmail, req.user.id) — async, non-blocking
  Return 200 { success: true, request: updatedRow }

executeErasure(dsrId, subjectEmail, agentUserId) — async internal function:
  Fetch all itineraries where client_email matches (case-insensitive) OR
  where phone_enc decrypts to a value associated with the subject
  (use popia_decrypt RPC for encrypted fields)
  For each matched itinerary:
    UPDATE SET client_name='[REDACTED]', phone_enc=null, passport_enc=null,
               sa_id_enc=null, flight_data=null, status='cancelled'
  Update the DSR notes: "Erasure completed {ISO date} by agent {agentUserId}. {N} record(s) redacted."
  Send erasure confirmation to subjectEmail via sendErasureConfirmation() from emailItineraryCompiler

## STEP 2 — Configure POPIA Encryption Key (Supabase Vault)

This key encrypts all PII at rest (passport numbers, SA ID numbers, phone numbers).
Losing this key means encrypted data cannot be recovered. Back it up securely.

1. Generate the key:
   node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
   Copy the output (64 hex characters).

2. Go to Supabase dashboard -> Settings -> Vault -> New Secret
   Name:  popia_aes_key
   Value: <your 64 hex characters>
   Save it.

3. Go to Supabase dashboard -> SQL Editor and run:
   ALTER DATABASE postgres SET app.popia_aes_key TO '<your 64 hex characters>';

### 11d. src/client/hooks/useRealtimeAssignments.js

  import { useEffect } from 'react'
  import { useQueryClient } from '@tanstack/react-query'
  import supabase from '../lib/supabaseClient'

  export function useRealtimeAssignments(itineraryId) {
    const queryClient = useQueryClient()
    useEffect(() => {
      const channel = supabase
        .channel('fleet-assignments-' + itineraryId)
        .on('postgres_changes', { event: '*', schema: 'public', table: 'fleet_assignments' }, () => {
          queryClient.invalidateQueries(['itinerary', itineraryId])
          queryClient.invalidateQueries(['availability'])
        })
        .subscribe()
      return () => { supabase.removeChannel(channel) }
    }, [itineraryId, queryClient])
  }

## 12. CROSS-CUTTING REQUIREMENTS
