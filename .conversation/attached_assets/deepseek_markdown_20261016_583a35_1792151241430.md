# 🛫 BUILD PROMPT — START

Build a complete production-ready flight tracking web application for South African airspace.
The app should be called **"SA Flight Tracker"** and track live aircraft positions in and around
South Africa, enriched with airline and airport reference data.

## ═══════════════════════════════════════════════════════════════════════════════
## TECH STACK (ALL FREE TIER)
## ═══════════════════════════════════════════════════════════════════════════════

- **Frontend:** React + Vite + TypeScript + TailwindCSS + shadcn/ui
- **Map:** Leaflet with react-leaflet (OpenStreetMap tiles, free, no API key)
- **Backend/Cron:** Cloudflare Workers (scheduled triggers)
- **Database:** Supabase (Postgres + Row Level Security)
- **Data Sources:**
  - OpenSky Network API (live aircraft positions — FREE, register for 4000 credits/day)
  - OpenFlights data dumps (static airports, airlines, routes — no key needed)
- **Hosting:** Cloudflare Pages (frontend) + Cloudflare Workers (backend)
- **Package Manager:** pnpm
- **Monorepo:** pnpm workspaces

## DATABASE SCHEMA (Supabase SQL — create these as migrations)
## ═══════════════════════════════════════════════════════════════════════════════

File: `supabase/migrations/001_initial_schema.sql`

```sql
-- ═══════════════════════════════════════════════════════════
-- REFERENCE DATA (from OpenFlights — seeded once)
-- ═══════════════════════════════════════════════════════════

CREATE TABLE airports (
  airport_id     INTEGER PRIMARY KEY,
  name           TEXT NOT NULL,
  city           TEXT,
  country        TEXT NOT NULL,
  iata_code      TEXT,
  icao_code      TEXT,
  latitude       DOUBLE PRECISION NOT NULL,
  longitude      DOUBLE PRECISION NOT NULL,
  altitude       INTEGER,
  timezone       DOUBLE PRECISION,
  tz_database    TEXT,
  type           TEXT,
  created_at     TIMESTAMPTZ DEFAULT NOW()
);

CREATE INDEX idx_airports_iata ON airports (iata_code);
CREATE INDEX idx_airports_icao ON airports (icao_code);
CREATE INDEX idx_airports_country ON airports (country);
CREATE INDEX idx_airports_location ON airports (latitude, longitude);

CREATE TABLE airlines (
  airline_id     INTEGER PRIMARY KEY,
  name           TEXT NOT NULL,
  iata_code      TEXT,
  icao_code      TEXT,
  callsign       TEXT,
  country        TEXT,
  active         BOOLEAN DEFAULT true,
  created_at     TIMESTAMPTZ DEFAULT NOW()
);

CREATE INDEX idx_airlines_iata ON airlines (iata_code);
CREATE INDEX idx_airlines_icao ON airlines (icao_code);

CREATE TABLE routes (
  id                        BIGSERIAL PRIMARY KEY,
  airline_code              TEXT NOT NULL,
  airline_id                INTEGER,
  source_airport_code       TEXT NOT NULL,
  source_airport_id         INTEGER,
  destination_airport_code  TEXT NOT NULL,
  destination_airport_id    INTEGER,
  codeshare                 BOOLEAN DEFAULT false,
  stops                     INTEGER DEFAULT 0,
  equipment                 TEXT,
  created_at                TIMESTAMPTZ DEFAULT NOW()
);

CREATE INDEX idx_routes_source ON routes (source_airport_code);
CREATE INDEX idx_routes_destination ON routes (destination_airport_code);
CREATE INDEX idx_routes_airline ON routes (airline_code);

-- ═══════════════════════════════════════════════════════════
-- LIVE FLIGHT DATA (upserted every ~3 minutes from OpenSky)
-- ═══════════════════════════════════════════════════════════

CREATE TABLE live_flights (
  id               BIGSERIAL PRIMARY KEY,
  icao24           TEXT NOT NULL,
  callsign         TEXT,
  origin_country   TEXT,
  longitude        DOUBLE PRECISION,
  latitude         DOUBLE PRECISION,
  baro_altitude    DOUBLE PRECISION,
  geo_altitude     DOUBLE PRECISION,
  on_ground        BOOLEAN DEFAULT false,
  velocity         DOUBLE PRECISION,
  true_track       DOUBLE PRECISION,
  vertical_rate    DOUBLE PRECISION,
  squawk           TEXT,
  spi              BOOLEAN DEFAULT false,
  position_source  INTEGER,
  last_contact     BIGINT,
  updated_at       TIMESTAMPTZ DEFAULT NOW(),
  UNIQUE(icao24)
);

CREATE INDEX idx_live_flights_callsign ON live_flights (callsign);
CREATE INDEX idx_live_flights_location ON live_flights (latitude, longitude);
CREATE INDEX idx_live_flights_updated ON live_flights (updated_at DESC);
CREATE INDEX idx_live_flights_on_ground ON live_flights (on_ground);

-- ═══════════════════════════════════════════════════════════
-- ROW LEVEL SECURITY
-- ═══════════════════════════════════════════════════════════

ALTER TABLE airports ENABLE ROW LEVEL SECURITY;
ALTER TABLE airlines ENABLE ROW LEVEL SECURITY;
ALTER TABLE routes ENABLE ROW LEVEL SECURITY;
ALTER TABLE live_flights ENABLE ROW LEVEL SECURITY;

-- Public read access for everyone
CREATE POLICY "Public read airports" ON airports FOR SELECT USING (true);
CREATE POLICY "Public read airlines" ON airlines FOR SELECT USING (true);
CREATE POLICY "Public read routes" ON routes FOR SELECT USING (true);
CREATE POLICY "Public read live_flights" ON live_flights FOR SELECT USING (true);

-- Only service role can write (worker uses service role key)
CREATE POLICY "Service write live_flights" ON live_flights
  FOR ALL USING (auth.role() = 'service_role');

-- ═══════════════════════════════════════════════════════════
-- HELPER FUNCTIONS
-- ═══════════════════════════════════════════════════════════

-- Cleanup stale flights (called by worker every 6 hours)
CREATE OR REPLACE FUNCTION cleanup_stale_flights()
RETURNS void AS $$
BEGIN
  DELETE FROM live_flights
  WHERE updated_at < NOW() - INTERVAL '30 minutes';
END;
$$ LANGUAGE plpgsql SECURITY DEFINER;

-- Get SA airports only
CREATE OR REPLACE VIEW sa_airports AS
SELECT * FROM airports
WHERE country = 'South Africa'
  AND iata_code IS NOT NULL
  AND iata_code != '\N'
ORDER BY city;

-- Get active SA airlines
CREATE OR REPLACE VIEW sa_airlines AS
SELECT * FROM airlines
WHERE country = 'South Africa'
   OR icao_code IN ('SAA', 'SAX', 'KEM', 'CAW', 'LNK', 'MNU', 'FLE', 'CAA')
ORDER BY name;
```

File: `apps/worker/src/index.ts`

Requirements:
1. Export a default object with `fetch` and `scheduled` handlers
2. The `scheduled` handler detects which cron triggered it:
   - `*/3 * * * *` → call fetchAndUpsertFlights()
   - `0 */6 * * *` → call cleanupStaleFlights()
3. The `fetch` handler exposes:
   - GET /health → returns { status: 'ok', timestamp }
   - GET /flights → returns current live flights (proxy from Supabase)
   - POST /admin/seed → one-time endpoint to seed OpenFlights data (protected by ADMIN_SECRET)
4. Use `ctx.waitUntil()` to allow async work after response
5. Comprehensive error logging with console.error
6. Retry logic: if OpenSky fetch fails, retry up to 3 times with exponential backoff

File: `apps/worker/src/opensky.ts`

Requirements:
1. Fetch an OAuth2 token from `https://auth.opensky-network.org/auth/realms/opensky-network/protocol/openid-connect/token` using client_credentials grant
2. Cache the token in memory (Workers isolate) until expiry
3. Function `fetchStates(bounds)` calls `https://opensky-network.org/api/states/all` with bounding box params
4. Parse the OpenSky state vector array (18 fields per state) into typed objects
5. Map OpenSky fields:
   - [0] icao24, [1] callsign, [2] origin_country, [3] time_position, [4] last_contact,
   - [5] longitude, [6] latitude, [7] baro_altitude, [8] on_ground, [9] velocity,
   - [10] true_track, [11] vertical_rate, [12] sensors, [13] geo_altitude,
   - [14] squawk, [15] spi, [16] position_source, [17] category
6. Handle anonymous fallback if OAuth credentials aren't configured
7. Return typed `Flight[]` array

File: `apps/worker/src/handlers/fetchFlights.ts`

Requirements:
1. Call fetchStates() with SA bounds
2. Filter out any states with null latitude/longitude
3. Trim callsigns (they're often padded with whitespace)
4. Upsert into live_flights using `onConflict: 'icao24'`
5. Log count of flights upserted
6. Handle Supabase errors gracefully

File: `apps/worker/src/handlers/cleanup.ts`

Requirements:
1. Call the Supabase RPC `cleanup_stale_flights()`
2. Log how many rows were deleted (return from RPC)

## ═══════════════════════════════════════════════════════════════════════════════

File: `scripts/seed-openflights.ts` (Node.js script, run locally)

Requirements:
1. Download these files from GitHub raw URLs:
   - `https://raw.githubusercontent.com/jpatokal/openflights/master/data/airports.dat`
   - `https://raw.githubusercontent.com/jpatokal/openflights/master/data/airlines.dat`
   - `https://raw.githubusercontent.com/jpatokal/openflights/master/data/routes.dat`
2. Parse the CSV format (note: fields are comma-separated, strings quoted with ")
3. Handle `\N` values as NULL
4. Insert into Supabase via service role key
5. Batch inserts (500 rows at a time) to avoid timeouts
6. Log progress every 1000 rows
7. Handle duplicate keys with upsert

**Airports.dat columns (order):**
Airport ID, Name, City, Country, IATA, ICAO, Latitude, Longitude, Altitude,
Timezone, DST, Tz database timezone, Type, Source

**Airlines.dat columns:**
Airline ID, Name, Alias, IATA, ICAO, Callsign, Country, Active

**Routes.dat columns:**
Airline, Airline ID, Source airport, Source airport ID, Destination airport,
Destination airport ID, Codeshare, Stops, Equipment

### 7. Troubleshooting

**Worker not writing data?**
- Check `wrangler tail` for real-time logs
- Verify `SUPABASE_SERVICE_ROLE_KEY` is set (not just anon key)
- Confirm RLS policies allow service_role writes

**Supabase project paused?**
- Free projects pause after 7 days of inactivity
- Your worker keeps it alive automatically
- If paused, go to dashboard → click "Restore"

**No flights showing?**
- It's possible there are literally zero aircraft in SA airspace at 3am
- Check `live_flights` table directly in Supabase
- Try widening the bounding box in wrangler.toml

**OpenSky 429 errors?**
- You've hit the rate limit (4000/day for registered)
- Reduce cron frequency from `*/3` to `*/5` minutes
